# Dashboard

Run from the repository root. Live page: `URL=https://earth-hub.diego-narvaez.workers.dev`. What the page shows and how
the Worker serves it: docs/technical/architecture.md#dashboard.

| Argument | Command |
| --- | --- |
| `check` (default) | `curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' $URL/`, `curl -s $URL/data/meta.json \| jq '{run_id, written_at, rows, bytes}'`, `curl -sI $URL/data/earthquakes.parquet \| grep -iE '^(etag\|content-length\|cache-control\|x-robots-tag)'`, the live build `curl -s $URL/ \| grep -o 'id="source"[^>]*>[^<]*' \| sed 's/.*>//'`, and `curl -s -o /dev/null -w '%{http_code}\n' $URL/privacy` (200) |
| `dev` | `make dashboard-dev` in the background; report the address when `Ready on` appears |
| `build` | `make dashboard-build` |
| `test` | `make test-dashboard` (~3–6 min) |
| `deployments` | `cd dashboard && npx --no-install wrangler deployments list 2>&1 \| grep -v '@'` |
| `deploy` | `make dashboard-deploy` |
| `trigger` | `make -s trigger-check 2>&1 \| grep -v '@' \| tail -1` (starts nothing), `cd dashboard && npx --no-install wrangler secret list 2>&1 \| grep -v '@'` (`GITHUB_TOKEN` listed, never its value), `make -s direct-runs LIMIT=3`, `gh run list --workflow direct.yml --limit 5` |

(In the table `\|` is a pipe; run it as `|`.)

- **Deploy only when the user's request says deploy**, and only from merged `main`. Afterwards run `check`, confirm
  `X-Robots-Tag: noindex, nofollow`, and that Wrangler's `schedule:` lines match the crons in
  `dashboard/wrangler.template.jsonc`. If Wrangler shows a value under `vars` that looks like a token, it is exposed:
  tell the user at once to revoke and rotate it (`make trigger-token`), and never repeat it.
- **Wrangler needs a login on this machine** (`npx --no-install wrangler login`, in `dashboard/`, once): without one,
  `deploy`, `deployments` and `trigger` fail asking for `CLOUDFLARE_API_TOKEN`. Never use `--temporary`.
- Filter lines with `@` from Wrangler's output: it can include the account's email.
- `dashboard/wrangler.jsonc` is generated by `scripts/dashboard_config.py`; never commit it. `dev` and `test` need
  `make dashboard-install` once.
- The page shows the last snapshot written to the bucket, never a deploy's: an export in full mode, a direct round in
  direct mode (`/eh-mode`).
- **The trigger's token** is the user's: `make trigger-token` in a terminal creates and stores it. Never run it for
  them, never ask for or print the token, and never have it set as a variable in the Cloudflare dashboard.

## Report

For `check`: the page's status and time, the snapshot's run, row count and age, the headers, and the live build. For
the others: the result, and the address or deployment version.
